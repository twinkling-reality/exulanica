# The tile record's half cannot land in Python alone, and the blocker is the version

The rename's remaining half is `TileRecord.city_seed` to `world_seed` at city grammar version 4.
This is what a Python-only attempt at it measured on 2026-09-19, from a committed and clean tree.
It was measured rather than reasoned from the version 3 precedent, which was two commits: the
Python grammar half at cd40963c and the web half at e7a24623 one commit later.

**The result is stronger than expected and it is not about the rename.** THE VERSION BUMP ALONE IS
ENOUGH. No field was renamed in the run below. Bumping the city grammar to 4 is by itself what
breaks the chain, so any change needing a new city version meets this, and a later reader should
not read this as a fact about `world_seed`.

## The chain, each link measured

**1. The Node tessellator refuses a city version 4 document, by name.** The committed fixture
document was copied and given `tile.version 4`, `grammar_versions[0].grammar_version 4` and
`grammars[0].grammar_version 4`, with the identity field renamed as city 4 would rename it, and
nothing else changed. Baked through `web/packages/loom-tess/src/node/cli.ts`:

    control, the committed document   baked: 703,588 bytes, container 4c76b9e0e2003088...,
                                      render_batch 185d7be6..., nav_envelope f6158941...
    probe, the same at version 4      REFUSED: "tile.fields.grammar_versions: pins city version 4,
                                      and this tessellator reads [2,3]"

The control is the same question on the same axis: the same bytes, one field apart, one baked and
one refused. Without it, a refusal could have been anything about the doctored file.

**2. The committed fixture is forced to the new version; it cannot be held back.** Bumping
`CITY_GRAMMAR_VERSION`, `STAGE_VERSION` and `TileRecord.RECORD_VERSION` to 4 and adding a
`city.v4.json` declaring the tile stage and record at 4, `tests/fixtures/city-v2/build_fixture.py`
regenerated `tile-document.json` pinning city version 4 throughout:

    tile.version                 4
    tile.grammar_versions        [{"grammar_id": "city", "grammar_version": 4, ...}]
    grammars[0].grammar_version  4

That is deliberate and correct: the coordinate unit lane made the builder read the version from the
grammar it is running, with the reason that "a fixture that named its own version would be a second
place the version is written down". So there is no arrangement where the Python code describes
version 4 and the committed fixture stays at 3, short of freezing a whole version 3 record class in
Python, which is a design change rather than a rename.

Two refusals on the way there are worth keeping, because both are guards doing their job and a
reader meeting them will otherwise think something is wrong:

    city declares stages [... ('tile', 3)], code has [... ('tile', 4)]
    city tile declares records [('city.tile', 3)], its validators take [('city.tile', 4)]

**3. With the fixture at version 4, `tests/test_bake_determinism.py` goes red: 15 failed, 3
passed.** Among them `test_the_tessellator_reads_the_grammars_own_table`, which is the descriptor
pin, and `test_two_node_bakes_under_one_key_write_identical_bytes`. That file hands the committed
fixture document to the Node tessellator, so it is a Python file whose FIX is not in Python.

## What it would take, in the tessellator's own words

`web/packages/loom-tess/src/core/record-shapes.ts` states the cost where a reader will meet it:

> Adding a grammar version is a new generated table, a rule per record kind in `expand.ts`, and a
> bump of `TESSELLATOR_SOURCE_VERSION`, which the bake stage's parameters carry.

All three are under `web/`, which tonight forbids. Beyond them, and not in that sentence:

    web/packages/loom-tess/src/core/city-v4.ts          generated by test/write-grammar-table.ts
    web/packages/loom-tess/src/core/record-shapes.ts    GRAMMAR_TABLES gains CITY_V4
    web/packages/atlas-core                             STATES its version list and derives nothing
    web/packages/app/src/dev/tiles/tile-conformance.owd a committed container, rebaked
    web/packages/app/test/generated-tile-golden.test.ts pins that container's digests
    web/packages/atlas-react/test/data-view/generated-subjects-city-v2.test.ts  reads the fixture

The atlas-core entry is the one that will bite, and the coordinate unit lane recorded why: two
components DERIVE the version list and cannot drift, and atlas-core STATES it because it may depend
on neither. Its `generatedRecordSubjectV2` holds an assertion binding each field it reads to one
shape across every version on the list, and THAT ASSERTION IS WHAT DECIDES WHETHER CITY 4 MAY JOIN.
Renaming `city_seed` changes the shape of a field the tile record carries, so whoever lands this
must answer that assertion rather than extend a list past it.

## The restore

The break was applied from a committed, clean tree and undone with `git reset --hard` plus a
scoped `git clean`. The restored state was PRINTED rather than trusted: `git status` clean, HEAD
unmoved, `city.v4.json` gone, `tile-document.json` back to
49be7eff98247649e1276b9c6ef5c441be9ad3289b220ba8135ce7e87aad8e77 and `record-shapes.json` back to
35603f3d7e5831de00dcd2e0ce9deca98faf84354274253aa384d50a7cbcfdb5, and all three version constants
back to 3.
