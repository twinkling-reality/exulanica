THE 304 IS NEW, AND IT IS THE CORRIDOR LANE'S FIX. Before today the route had no If-None-Match
branch and a plain Starlette Response does no conditional handling, so every revalidation was
answered 200 with the whole container while the documentation said a reload cost nothing. This lane
found that by reading `read_tile_bytes` and `starlette/responses.py` rather than the docstring, the
corridor lane implemented the branch with its own route tests, and the "not-modified" line above is
that branch working. The loader sends If-None-Match either way and prefers the held digest, so it
would have been correct with or without the fix.

PROVED ON A SECOND RUN, with a second credential the corridor lane supplied: one that authenticates

  full credential, unknown key          404 unknown_reference
                                        "no such baked tile"

THE TWO ARE NOT BYTE FOR BYTE THE SAME, and the earlier unit test in this lane assumed they were.
The permission floor refuses an id-addressed route before the route's own function runs, so that
refusal carries the floor's detail and none of the route's headers. The corridor lane measured this,
pinned it in a test of its own, and decided not to make them identical: a credential without the
permission is told the same thing about every id, existing or not, so it still cannot learn which
ids exist, while an authorised caller keeps a detail that helps it debug. The pair that is stable,
and the only pair this loader relies on, is the status and the code: 404 and unknown_reference. The
unit test now asserts exactly that, and asserts as well that neither refusal's message claims which
of the two it was.

  texture sets asked for         none. The test fails the run if one is requested, because a container
                                 that never parsed must not cause a single set to be fetched

So the digest check and the reader are two separate guarantees and both are load bearing. The digest
says the bytes are the ones the row names; it says nothing about what those bytes ARE. A row can name
74 bytes of ASCII, and the row would be right. Only the reader can refuse a thing that is not a tile,
and the refusal names the reason rather than failing somewhere later with a parse error nobody can
place.

This was measured headlessly, with no renderer: the refusal happens in the reader before any texture,
mesh or device is touched, which is itself the property worth having. A picture of the same refusal on
screen is worth taking when a browser is free, but it would show the same sentence this run printed.
